    **iter-52 KI#52 — Jinja-based template inference sub-rule**: when the GGUF-embedded (or HF-cached) Jinja is available, `detect_template()` (`template_detector.py:601-635`) additionally calls `_infer_template_from_jinja(jinja_source)` AFTER `_resolve_template_from_arch()`. The helper inspects the Jinja source for telltale markers (`<|eot_id|>` → Llama-3, `[INST]` → Mistral, `<|im_start|>` → ChatML, etc.) and overrides `resolved_name` when the Jinja clearly indicates a different family than the arch heuristic. This fixes the bug where `arch="llama"` (which conflates Llama-3, Llama-2, Mistral, Vicuna) always returned `"llama-3"` even for Mistral-family models — Rocinante-X-12B (`arch=llama` + Mistral-style Jinja) now correctly resolves to `"mistral-v0-1"` → stop tokens `['</s>']` (was `['<|eot_id|>']` pre-iter-52). Verified per https://platform.claude.com/docs/en/build-with-claude/extended-thinking. iter-85 forces `temperature=1.0` + makes `budget_tokens` adaptive (`min(max_tokens-1024, max(1024, int(max_tokens*0.6)))` — was hardcoded 10000).
    - **OpenAI** (iter-85): CRITICAL bugfix — pre-iter-85 used the deprecated `max_tokens` parameter which FAILS for o-series (o1, o3, o4-mini) — must use `max_completion_tokens` (deprecated since Sept 2024). Verified per https://community.openai.com/t/why-was-max-tokens-changed-to-max-completion-tokens/938077 + https://github.com/simonw/llm/issues/724. iter-85 always uses `max_completion_tokens` (works for ALL current models per OpenAI migration guide, not just o-series). New `_build_max_tokens_param()` helper centralises the param-name logic.

## §5. Local LLM Request Flow

```

  → interface_signals.py builds context_messages
  → prompt_engine.build_system_prompt_blocks()
    → Creates multiple system blocks (prompt, char info, lorebook, soul memory, state)
    → validate_messages_for_llama() checks for issues
    → Returns messages list + activated_lorebook
  → AIFactory.get_provider("Local LLM")
    → LocalProvider(port=48596, advanced_params=...)
  → provider.generate_stream(messages, **_sampling)  # KI#49 (iter-40): sampling params forwarded

    → Sends to http://127.0.0.1:48596/v1/chat/completions
    → Streams chunks with stream_options include_usage
    → _log_usage() logs prompt_eval tokens
  → UI displays streamed response
```

## §6. Local LLM Restart Flow (KI#50, iter-41 → fixed iter-42)

```
User toggles reasoning_mode checkbox OR changes chat_template combobox
  → interface_signals.py signal handler:
      on_checkBox_reasoning_mode_stateChanged()
      on_comboBox_chat_template_changed()
  → configuration.update_main_setting() — persists to settings.json
  → main_window.log_runtime_context_delta() — logs "RUNTIME CONTEXT DELTA | ..."
  → self._maybe_restart_local_server(trigger)        # KI#50 (iter-41, fixed iter-42)
      → lsm = getattr(self, "local_server_manager", None)   # iter-42 fix: instance B
                                                            # (NOT self.main_window.local_server_manager
                                                            #  which is the orphan instance A — see Pitfall #14)
      → asyncio.create_task(lsm.restart_server_async())     # fire-and-forget
  → Qt event loop returns immediately (checkbox feels responsive)
  
[later, in qasync background task]
  → LocalServerManager.restart_server_async()  # runs on instance B (the one with the live subprocess)
      → async with self.restart_lock   # serializes concurrent restarts
      → if server_process is None: no-op (settings already in settings.json,
                                          will apply on next start_server_async())
      → else:
          → stop_server()              # terminates subprocess, cleanup_lock_file()
          → asyncio.sleep(1)           # TCP TIME_WAIT release on Windows
          → start_server_async()       # reads new flags from settings.json
          → poll model_loaded until True  # waits for "all slots are idle"
          → log "[KI#50] llama-server restarted successfully with updated CLI flags."
```

### iter-67: Free-form Jinja override — new settings.json keys

Two new keys in ``main_settings``:

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| ``custom_jinja_override`` | string | ``""`` | Jinja source text for the free-form override. Empty = no override. When non-empty, ``local_server_manager.py`` writes it to ``app/data/custom_template.jinja`` and passes ``--chat-template-file <path>`` to llama-server (overrides the combo box ``chat_template`` and the auto-detected GGUF-embedded template). |
| ``diagnostics_dialog_geometry`` | string | ``null`` | Hex-encoded ``QByteArray`` from ``QDialog.saveGeometry()`` for the expanded diagnostics dialog. Absent = no saved geometry (dialog uses default 1000x700 size). |

Both keys are backward compatible — ``get_main_setting()`` returns ``None`` for missing keys, which is treated as "no override" / "no saved geometry".
